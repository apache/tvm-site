Core TVMScript#

TIRx kernels use tvm_tirx.script.tirx for the parser and core IR builders:

from tvm_tirx.script import tirx as Tx

Tx.alloc_tensor(...)

Tile ops and backend-specific namespaces are documented separately in Tensor Instruction Authoring API, CUDA Authoring and Support APIs, and Direct PTX Instructions. For the relationship between these authoring layers and TIRx IR, see The Programming Model.

Parser entry points#

Public canonical TVMScript dialect namespace.

tvm_tirx.script.tirx.function(function: LambdaType | None = None, **options: Any) → Any

Parse a Python function into a function of the selected IR language variant.

Parameters:

  • function (Callable, optional) – The function to be parsed. May be omitted to use the decorator with keyword options, such as @T.function(private=True).

  • private (bool, optional) – Whether the function should be treated as private. A private function has no global symbol attribute; a public function has a global symbol matching its name. Defaults to False.

  • check_well_formed (bool, optional) – Whether to check that the constructed function is well formed. Defaults to True.

  • persistent (bool, optional) – For T.function, mark the resulting function as a persistent kernel. Defaults to False. See tvm_tirx.tirx.script.ir_builder.function().

  • pure (bool, optional) – For R.function, declare whether the function is pure, meaning that it has no observable side effects. Defaults to True. See tvm.relax.script.ir_builder.function_().

  • **options – Keyword options are forwarded to the selected language variant’s function_() hook, except check_well_formed, which controls parser validation. Options supported by only one language variant are not shared between T.function and R.function.

Returns:

result – The parsed function, or a decorator when function is omitted. Class members retain their Python functions until the enclosing module is constructed.

Return type:

Function or relax.Function or Callable

tvm_tirx.script.tirx.inline(function: LambdaType | None = None, **options: Any) → Callable[[...], Any]

Decorate a helper that constructs IR in its caller’s active frames.

Parameters:

  • function (Callable, optional) – The helper function. May be omitted to supply keyword options.

  • hygienic (bool, optional) – Whether the helper resolves symbols in its definition environment instead of its calling environment. Defaults to True. T.macro and R.macro capture values at definition time; T.inline refreshes captured closure cells when called.

  • **options – Keyword configuration for this helper decorator. hygienic controls name lookup as described above; other options are accepted but are not consumed or forwarded to builder hooks.

Returns:

result – The construction helper, or a decorator when function is omitted.

Return type:

Callable

Notes

T.inline follows Python lexical scoping with late binding of captured closure cells. Its return statements produce Python values, as do those of R.macro. T.macro emits returns in the active primitive function.

Examples

An inline helper can read values from its enclosing scope:

import tvm_tirx
from tvm_tirx.script import tirx as T
x_value = 128

@T.inline
def capture(A, B):
    B[()] = A[x_value]  # x_value resolved from enclosing scope

@T.function
def use(A: T.Tensor((1024,), "int32"), B: T.Tensor((), "int32")) -> None:
    capture(A, B)       # Produces B[()] = A[128]
tvm_tirx.script.tirx.jit(func: LambdaType | None = None, *, private: bool = False, check_well_formed: bool = True, persistent: bool = False) → TIRJit | Callable[[LambdaType], TIRJit]

Decorator: capture the kernel and defer parsing until .specialize().

Use @T.jit (instead of @T.function) when the kernel takes compile-time parameters annotated with T.constexpr or runtime parameters that may be removed with T.Optional. The resulting object exposes .specialize(**const_args), which returns a tvm_tirx.tirx.Function.

Parameters:

  • func (types.FunctionType or None, optional) – Function supplied by a definition-site @T.jit application. None, the default, returns a decorator for @T.jit(**options).

  • private (bool, optional) – Omit the function’s public global symbol when True. Default is False.

  • check_well_formed (bool, optional) – Validate each constructed specialization. Default is True; this option controls the parser separately from the function builder kwargs.

  • persistent (bool, optional) – Mark constructed specializations as persistent kernels. Default is False.

Returns:

Deferred kernel, or its definition-site decorator when func is None.

Return type:

TIRJit or Callable[[types.FunctionType], TIRJit]

Raises:

  • TypeError – If the decorated value is not a Python function.

  • SyntaxError – If application occurs after definition or uses an unsupported bare or preconfigured callable alias instead of a qualified namespace decorator.

  • OSError – If the function’s source cannot be recovered.

Examples

Specialize compile-time dimensions before compiling the kernel:

from __future__ import annotations

from tvm_tirx.script import tirx as T

@T.jit
def add(
    A: T.Tensor((N,), "float32"),
    B: T.Tensor((N,), "float32"),
    *,
    N: T.constexpr,
):
    for i in T.serial(N):
        B[i] = A[i] + 1.0

kernel = add.specialize(N=1024)  # returns a Function

@T.jit
def guarded(
    optional: T.Optional(T.Tensor((1,), "int32")),
    output: T.Tensor((1,), "int32"),
):
    if T.constexpr(optional is not None):
        output[0] = optional[0]
    else:
        output[0] = 0

present = guarded.specialize()
absent = guarded.specialize(optional=None)

Core IR builder#

Common statement frames and construction helpers live in tvm_tirx.script.ir_builder.frame and tvm_tirx.script.ir_builder.stmt. The TIRx namespace re-exports them alongside its function, tensor/layout, and execution scope builders. Native shared statement builders live under include/tvm/script/ir_builder and src/script/ir_builder; dialect-specific thread-placement and tensor alias policies remain in the TIRx/S-TIR builders.

Tracing ordinary Python#

The native builders also support frontends that execute ordinary Python to construct IR. IRBuilder.line_trace_scope() records file-backed Python source lines. Script-facing void calls automatically emit into an active IRBuilder, with or without line tracing:

from tvm_tirx.script import tirx as Tx
from tvm_tirx.script.ir_builder import IRBuilder
from tvm_tirx.tirx.script import ir_builder as I

with IRBuilder() as builder:
    with I.function_():
        I.func_name_("synchronize")
        with builder.line_trace_scope():
            with Tx.device_entry(
                launch=Tx.cuda.LaunchConfig(grid=1, block=32)
            ):
                Tx.ptx["bar.sync"](0)
function = builder.get()

Auto emission applies to script-facing calls through Tx, including PTX and backend namespaces. A void call returns an AlreadyEmitted receipt; passing that receipt to evaluate or emit_ does not emit it again. Calls producing values remain expressions. Raw IR constructors such as tvm_tirx.ir.Call, tvm_tirx.tirx.op and raw backend APIs remain pure even inside an IRBuilder. Line tracing only supplies source locations; it neither enables nor disables emission. The trace scope restores its previous trace and location state on exit, including exceptional exits, and applies only to its owning builder. Explicit with_loc and at_ locations compose with the traced lines.

Line tracing excludes TVM and standard-library implementation files. Frontends can supply additional directories using line_trace_scope(exclude_paths=(... ,)). User helpers retain their own source line and the caller’s location through CallSiteLoc. These locations cover whole lines; the TVMScript parser records expression ranges. Python loops and branches execute during construction; use the native statement frames to construct runtime control flow.

Tensor parameters and shared dimensions#

Traced frontends can bind native types directly with I.arg_. A shared symbolic dimension imposes the same size constraint on multiple tensor arguments:

n = Tx.Var("n", Tx.int64)
# Inside an I.function_() frame:
x = I.arg_("x", Tx.Tensor((n,), Tx.float32))
y = I.arg_("y", Tx.Tensor((n,), Tx.float32))

The compiled host entry accepts tensor arguments, including PyTorch tensors, and checks their dtype, rank and shared dimensions. Use independent symbolic dimensions for unrelated sizes. If the same dimension is also an explicit scalar parameter, I.arg_("n", n) binds that existing Var. x.data and x.ptr_to(indices) provide pointers inside the function. Tx.Ptr retains its raw-pointer ABI and does not imply tensor argument conversion.

Explicit register fragments#

A register fragment is an ordinary local tensor with an explicit layout. For a two-CTA Layout-B accumulator, define the TMEM and register layouts outside the kernel:

from tvm_tirx.backend.cuda.axis import tid_in_wg
from tvm_tirx.backend.cuda.layout import tmem_mma_operand_layout
from tvm_tirx.tirx.layout import TileLayout, S

layout_b = tmem_mma_operand_layout(
    "D", (64, 128), "float32", M=128, cta_group=2)
register_layout = TileLayout(S[(64, 2, 64) : (1 @ tid_in_wg, 64 @ tid_in_wg, 1)])

Inside the kernel, declare the accumulator over its allocated TMEM address, allocate the register fragment, and prepare matching instruction views:

C = Tx.cuda.decl_tmem(tmem_address, ty_args=[
    Tx.Tensor((64, 128), "float32", scope="tmem", layout=layout_b)
])
frag = Tx.alloc_tensor(ty_args=[
    Tx.Tensor((64, 128), "float32", scope="local", layout=register_layout)
])
C_words = C.rearrange("(wh r) (wl c) -> (wl wh) r c",
                      wh=2, r=32, wl=2)
frag_words = frag.rearrange("(wh r) (wl c) -> (wl wh) r c",
                            wh=2, r=32, wl=2)
Tx.cuda.tile.apply(
    Tx.ptx["tcgen05.ld.sync.aligned.32x32b.x64.b32"],
    frag_words, C_words, scope="warpgroup")
Tx.ptx.tcgen05.wait__ld.sync.aligned()

tmem_address must name a live allocation with at least 64 columns. The readback requires a full active warpgroup. Complete the producing MMA’s commit/mbarrier wait and the required tcgen05.fence::after_thread_sync before the load.

Layout B stores logical C[i,j] in TMEM lane i + 64*(j//64) and column j%64. The register layout assigns that same element to thread i + 64*(j//64) and local slot j%64. The views above both have shape (4,32,64): warp=2*wl+wh chooses the physical 32-lane slab, r selects its row, and c selects its 64 columns. Each warp issues one .32x32b.x64 instruction and each lane receives 64 registers. No temporary copy is needed. wait::ld makes the loaded registers available to subsequent instructions; it does not wait for an earlier MMA.

See tcgen05.ld / tcgen05.st for other native shapes, pack/unpack, and a complete store/load example.
