mov#

Call parameters#

T.cuda.tile.apply(T.ptx[opcode], *operands, scope="thread", **parameters)

Operand order: dst, src; or the explicit packing/unpacking register groups.

Parameter

Type / default

Meaning

scope

static str; default “thread”

Execution scope; group axes follow Explicit CUDA tile patterns. It does not elect an issuing thread.

pred

runtime bool; default None

Execute the instruction when true; None is unconditional.

preserve_dst

static bool; default False

For a predicated register result, retain the initialized destination when pred is false; otherwise the inactive result is undefined.

Only the parameters listed here are instruction parameters. Opcode qualifiers are written in T.ptx[opcode].

Data representation#

Each operand uses the scalar PTX register type or its equal-width bit container. A packed f16x2/bf16x2 value occupies one b32 container; f32x2 occupies one b64 container. The final tensor axis counts native registers, not the packed scalar elements. Rounding, saturation, signedness and packing are selected in the opcode.

Operand specification#

mov copies register bits or assembles/disassembles a native register group. It performs no numeric conversion and cannot change which thread owns a value. Use cvt for conversion and ld / st for memory.

The scalar form ends both tensor operands in (1,). All earlier axes after the execution-group prefix are repeats. A scalar source expression can broadcast, for example to fill a register tile. Vector-group mov forms instead use the group length declared by that PTX form; each input/output word remains an explicit operand slot.

Legality conditions#

All tensor operands are local registers owned by the issuing thread. Their group/repeat shapes agree; the final extent equals that operand’s native register count (one for a scalar operand). Scalar expressions are allowed for single-register read inputs and broadcast across repeats. Destination slots must not overlap. Register storage strides are in container elements; they need not be one. The selected PTX form validates operand types.

Code generation#

For each group and row-major repeat coordinate, bind each tensor’s final register axis in increasing order and emit one selected instruction. A scalar input is reused. No packing, memory staging or synchronization is inserted. The number of expanded instructions per issuing thread is the product of repeat extents; downstream compiler optimizations may simplify unused or constant results.

Examples#

Example: filling and copying separated register slots#

from tvm.script import tirx as T
from tvm.tirx.layout import S, TileLayout

gapped = TileLayout(S[(4, 1) : (2, 1)])


@T.function
def register_move(Out: T.Tensor((4, 1), "uint32")):
    T.device_entry(launch=T.cuda.LaunchConfig(grid=1, block=1))
    a = T.alloc_local((4, 1), "uint32", layout="default")
    b = T.alloc_local((4, 1), "uint32", layout=gapped)
    T.cuda.tile.apply(T.ptx["mov.b32"], a, T.uint32(17))
    T.cuda.tile.apply(T.ptx["mov.b32"], b, a)
    T.cuda.tile.apply(T.ptx["st.global.b32"], Out, b)

The first call emits four moves of the same constant. The second emits four moves to offsets 0, 2, 4, and 6 of b; its gaps require no extra remap buffer. All four output values are 17. Ordinary compiler optimizations may subsequently eliminate redundant moves; the tile expansion itself selects no alternative instruction or ownership map.

pred is an ordinary runtime predicate. For a predicated output that must keep its old value, initialize it and pass preserve_dst=True. A suppressed move is not a zero fill. Destination repeats must not overlap each other.

For packed arithmetic, a bit reinterpretation such as halves.view("uint32") can expose the existing low/high halfword storage without a mov. Use an explicit group mov when assembling separately stored values. Group arity and carrier dtype must agree with the selected native form; the pattern does not guess a packing arrangement.

Implementation: python/tvm/backend/cuda/tile/patterns/register.py.
