Functions and Modules#

In this chapter, we will introduce functions and modules as the structures that organize IR programs. A function combines parameters, a result type, and a statement body; a module collects named function definitions. Compiler passes use these structures to inspect a function’s interface and implementation and locate definitions through global references.

Functions#

We can inspect a small CPU function to see how its parameters and body fit together. It accepts two tensors of length n and writes each input value plus one to the output:

from tvm_tirx.script import tirx as T

n = T.dynamic("n")


@T.function
def add_one(A: T.Tensor((n,), T.float32), B: T.Tensor((n,), T.float32)):
    for i in range(n):
        B[i] = A[i] + 1

@T.function parses the definition into a tirx.Function object, which the name add_one now refers to. Its params field holds A and B, and its body holds the loop.

tirx.Function inherits from ir.BaseFunc, the common base class for IR function definitions. The base class provides attrs for named function properties. tirx.Function adds the tensor program’s parameters, return type, and statement body.

The main fields of tirx.Function are:

Field

Meaning

params

Parameter variables in calling order.

ret_type

The declared return type.

body

A SeqStmt, or None for a declaration without an implementation.

attrs

An ir.DictAttrs containing named function properties.

The loop has its own body containing the tensor store. We can print these nested bodies and expand the function’s return type:

from tvm_tirx import ir

print(ir.format_tree(add_one, expand=[(ir.BaseFunc, "ret_type")]))

The output is:

Function
├── params[0]: A = Var(ty=TensorType(shape=[n], dtype=float32))
├── params[1]: B = Var(ty=TensorType(shape=[n], dtype=float32))
├── ret_type: TupleType
│   └── fields: []
└── body: SeqStmt
    └── seq[0]: For(begin=IntImm(value=0), end=n)
        ├── var: i = Var(ty=int32)
        └── body: SeqStmt
            └── seq[0]: TensorStore(dest=B, indices=[i])
                └── value: Add
                    ├── a: TensorLoad(source=A, indices=[i])
                    └── b: FloatImm(value=1.0)

add_one.ty stores an ir.FuncType describing the function’s signature: its parameter types and return type. We can inspect these types directly:

signature = add_one.ty
parameter_types = signature.arg_types
return_type = signature.ret_type

parameter_types contains the tensor types of A and B in calling order. The entries in add_one.params are the variables themselves. return_type is the same type stored in add_one.ret_type: an empty tuple type, ir.TupleType([]), indicating no return value. This function writes its results into B.

A function can also return a value explicitly. This helper adds one to a scalar and returns the result:

@T.function(private=True)
def add_one_scalar(value: T.float32) -> T.float32:
    return value + 1

The return annotation -> T.float32 sets its ret_type to ir.PrimType("float32"), and the return becomes an ir.Return statement in its body. The result of add_one goes into an output parameter; the result of add_one_scalar is a return value.

So far, @T.function has built a function object for us from source code. Compiler code can also build this kind of object directly with tirx.Function. To focus on the function constructor, we can reuse the parameters and loop already stored in add_one:

from tvm_tirx import ir, tirx

A, B = add_one.params
loop = add_one.body[0]

A and B are the IR parameter variables, and loop is the ir.For shown in the tree above. We can pass these objects to the constructor to create another function with the same computation:

ir_function = tirx.Function([A, B], loop, ret_type=ir.TupleType([]))

The new function takes A and B as parameters and runs loop as its body. The constructor wraps this single statement in a SeqStmt. ret_type=ir.TupleType([]) specifies that the function returns no value; its loop writes the result to B. A function that returns a value needs its return type set through ret_type; the constructor does not infer it from the body.

We will put ir_function in a module and compile it below. To make the compiled function available under the name "add_one", we set its global_symbol attribute:

ir_function = ir_function.with_attr("global_symbol", "add_one")

with_attr, inherited from ir.BaseFunc, returns a new function with this entry in attrs. For public TVMScript functions, @T.function sets global_symbol to the Python function name automatically.

Modules#

A program can contain several functions that call one another. ir.IRModule collects their definitions so compiler passes can find the functions being called and transform the program as a whole. We can put the function we just constructed, ir_function, in a module under the name "add_one":

module = ir.IRModule({"add_one": ir_function})

The module’s functions field maps global references to function definitions. Each key is an ir.GlobalVar, and each value is a function definition whose class inherits ir.BaseFunc. Here, that value is our tirx.Function object, ir_function. The constructor creates a GlobalVar named "add_one" from the string key and associates it with this function:

print(ir.format_tree(module.functions, max_depth=3))

The output is:

Map
├── [0][0]: GlobalVar(name_hint='add_one')
└── [0][1]: Function
    ├── params: Array(...)
    └── body: SeqStmt(...)

The map displays each entry as a key/value pair: [0][0] is the global reference and [0][1] is its function definition. max_depth limits the display, so ... marks fields left unexpanded. The GlobalVar serves as a reference; the function body belongs to the associated tirx.Function. We can retrieve the reference by name, then use it to look up the definition:

add_one_ref = module.get_global_var("add_one")
function = module[add_one_ref]

The first line returns the GlobalVar key, and the second returns the tirx.Function stored under it. module["add_one"] retrieves the same definition directly by name. A call can use add_one_ref as its op to identify this function. The call records the reference and its arguments; the module stores the definition that the reference identifies.

The name "add_one" used in this lookup is the function’s name within the module. The function’s attrs["global_symbol"] specifies its exported name for code generation. Both names are "add_one" in this example, but they serve these separate purposes.

tvm_tirx.compile accepts a module as well as a standalone function. We can compile module for the CPU with LLVM, then call its exported add_one function with input and output tensors:

import torch

import tvm_tirx

compiled = tvm_tirx.compile(module, target="llvm")
a = torch.arange(10, dtype=torch.float32)
b = torch.empty(a.shape, dtype=a.dtype)
compiled["add_one"](a, b)

compiled["add_one"] retrieves the exported function. The call reads a and writes a + 1 into b.
