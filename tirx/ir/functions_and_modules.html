Functions and Modules#

In this chapter, we will introduce functions and modules as the structures that organize IR programs. A function combines parameters, a result type, and a statement body; a module collects named function definitions. Compiler passes use these structures to inspect a function’s interface and implementation, locate definitions through global references, and replace an implementation while preserving references to it.

Functions#

For tensor programs, use @T.function to define functions in TVMScript, as in our sigmoid example. The decorator produces a tirx.Function IR object. To help users better understand the IR, we also show how to construct the same representation directly through the IR API.

ir.BaseFunc is the base class for all function definitions and is also an expression. Its attrs field holds named function properties:

Field

Value type

Meaning

attrs

ir.DictAttrs

Named function properties.

tirx.Function extends ir.BaseFunc with parameters, a result type, and a statement body:

Field

Meaning

params

Parameter variables in calling order.

ret_type

The declared result type.

body

A SeqStmt, or None for a declaration without an implementation.

The parameter and result types form the function’s signature, available as an ir.FuncType through ty. The global_symbol entry in attrs specifies the function’s exported name for code generation. For public functions, @T.function sets it to the Python function name by default. The IR API example below sets it explicitly with with_attr.

The program defines a function with input, bias, and output tensors. Its IR definition combines these three parameters with the batch and channel loops:

function = tirx.Function([X, bias, Y], batch_loop, ret_type=ir.TupleType([]))
function = function.with_attr("global_symbol", "bias_sigmoid")

batch_loop contains a channel loop that processes one element at a time. The function writes activated values into Y; ir.TupleType([]) declares that it returns no value. The input and output types have shape (2*n, channels). The symbol n, whose value the compiled function derives from the tensor shapes at runtime, is used in these types and the loop bound.

Modules#

ir.IRModule organizes named functions into a program and lets us look up their definitions. An ir.GlobalVar is an expression that refers to a function stored in the module. This differs from the ir.Var objects used for parameters and local values in our example. The module associates each function reference with its ir.BaseFunc definition, such as a tirx.Function.

In the bias + sigmoid example, one module keeps two model specializations. The same factory builds kernels for 128-channel and 130-channel outputs, each with its own exported name:

channels_128 = make_bias_sigmoid(128).with_attr("global_symbol", "bias_sigmoid_128")
channels_130 = make_bias_sigmoid(130).with_attr("global_symbol", "bias_sigmoid_130")
module = ir.IRModule({"bias_sigmoid_128": channels_128, "bias_sigmoid_130": channels_130})

Both accept tensors with a runtime row count of 2*n. Each specialization uses a scalar loop over its channels. Their tensor types record the different widths.

Use module.get_global_var(name) to retrieve the ir.GlobalVar reference for an existing function:

entry = module.get_global_var("bias_sigmoid_130")
function = module[entry]

entry is the function’s ir.GlobalVar reference; module[entry] and module["bias_sigmoid_130"] retrieve its current definition. A compiler pass can replace that definition while keeping entry. If the replacement preserves the function’s calling interface, calls using this reference can remain unchanged.

For example, a compiler can keep the original expanded sigmoid and build another module that uses the named prim.sigmoid operator. The factory’s activation argument selects this representation:

variant = module.clone()
replacement = make_bias_sigmoid(130, activation=ir.prim.sigmoid)
variant[entry] = replacement.with_attr("global_symbol", "bias_sigmoid_130")

variant keeps the 128-channel definition and replaces the 130-channel definition with one that calls prim.sigmoid. The replacement keeps the same tensor interface and exported name, so variant[entry] now retrieves the new implementation through the existing global reference. The original module still contains the expanded sigmoid expression.
