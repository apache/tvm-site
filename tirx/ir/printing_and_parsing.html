Printing and Parsing

Printing and Parsing#

Printing renders IR as readable TVMScript, and parsing constructs IR from Python source. Compiler extensions can reuse these interfaces to generate programs, inspect the resulting IR, and reconstruct programs from source. Extensions can customize how source builds IR through builder namespaces and how IR is rendered through printer hooks.

For example, this function increments every element of a float32 tensor with shape (2*n, 128). Save the code in a Python file so the decorator can inspect its source:

from __future__ import annotations

from tvm_tirx import ir, tirx
from tvm_tirx.script import from_source
from tvm_tirx.script import ir as I
from tvm_tirx.script import tirx as T


@T.function
def f(n: T.int64, A: T.Tensor((2 * n, 128), "float32")) -> T.void:
    for i, j in T.grid(2 * n, T.int64(128)):
        A[i, j] = A[i, j] + T.float32(1)

@T.function parses the definition into a tirx.Function. The future import postpones annotation evaluation until the parser reads the definition, so n in the tensor annotation can resolve to the first IR parameter. The tensor’s shape and the loop bound refer to that same variable, keeping 2*n symbolic in both places. The loops and indexing construct IR; the tensor computation runs when the compiled function is called.

Script helpers let generated functions reuse parts of a computation. An @T.inline helper can return an expression, while @T.macro inserts statements into the function being built. These helpers separate the element addition from the tensor write:

@T.inline
def increment(value):
    return value + ir.const(1, value.ty)


@T.macro
def increment_at(A, i, j):
    A[i, j] = increment(A[i, j])

increment constructs the addition, and increment_at writes its result back to the tensor. ir.const(1, value.ty) gives the constant the element’s type, so the helpers also work with other element types.

An ordinary Python function can choose a shape and dtype, construct a @T.function definition, and return the resulting tirx.Function. Here, make_increment builds a function with the requested column count and element type:

def make_increment(width, dtype="float32"):
    if not isinstance(width, int) or width <= 0:
        raise ValueError("width must be a positive Python integer")

    @T.function
    def generated(n: T.int64, A: T.Tensor((2 * n, width), dtype)) -> T.void:
        for i, j in T.grid(2 * n, T.int64(width)):
            increment_at(A, i, j)

    return generated


wide = make_increment(128)
narrow = make_increment(64, "float16")

width and dtype are Python values read while the factory runs. wide has a fixed second dimension of 128 and float32 elements; narrow has a second dimension of 64 and float16 elements. Their first dimension remains 2*n, where n is an IR parameter supplied when the compiled function is called. The width check and function construction run while make_increment executes; the generated loops describe the later tensor computation. Generating IR with Python logic in this way is metaprogramming.

Printing lets you inspect what this Python code generated:

source = wide.script()
print(source)

script() returns source text. The printed wide function contains these loops, using the selected width and element type:

for i in range(T.int64(0), T.int64(2) * n):
    for j in range(T.int64(0), T.int64(128)):
        A[i, j] = A[i, j] + T.float32(1.0)

The helper calls have expanded into an addition and a tensor write. The source also declares n with T.dynamic, which creates a symbolic ir.Var for reuse in the signature and tensor shape. You can also print the result of a pass or smaller parts of a program: wide.params[1].ty.script() renders its tensor type, and wide.body[0].script() renders its outer loop.

For interactive inspection, wide.show() displays highlighted source. See show() for options such as line numbers and underlining IR objects.

from_source parses a source string into a new IR object. Names used in the text must be supplied by its imports or the extra_vars dictionary. The printed source refers to T, but its import is a comment by default, so this example supplies T through extra_vars:

restored = from_source(source, extra_vars={"T": T})
ir.assert_structural_equal(wide, restored)

The structural comparison checks that the reconstructed program has the same operations, types, and variable bindings. Its printed syntax can differ from the original: for example, T.grid becomes nested loops.

The same process works for modules. @I.ir_module turns a class containing function definitions into an ir.IRModule. Here it collects both generated variants, which can then be printed and parsed together:

@I.ir_module
class Kernels:
    wide = wide.with_attr("global_symbol", "wide")
    narrow = narrow.with_attr("global_symbol", "narrow")


module_source = Kernels.script()
restored_module = from_source(module_source, extra_vars={"I": I, "T": T})
ir.assert_structural_equal(Kernels, restored_module)

To include import statements in the printed text, set ir.comment_imports to False. The parser can then resolve I and T from those imports, without extra_vars. This is useful when saving the source for another process:

standalone_source = Kernels.script(extra_config={"ir.comment_imports": False})
standalone_module = from_source(standalone_source)
ir.assert_structural_equal(Kernels, standalone_module)
