IR Overview#

TIRx gives developers and agents direct access to the programs and transformations at each stage of compilation. They can inspect the intermediate program, apply an existing pass, or add their own compiler components.

TIRx represents a program as a tree of intermediate representation (IR) nodes, such as functions, statements, and values. The tree is similar to the abstract syntax tree (AST) of Python code, but in a more structured, typed form. A compiler pipeline analyzes and transforms this tree step by step to produce target code. The tvm_tirx.script interfaces print the IR as TVMScript, a Python-based notation for tensor programs. For example, this TVMScript definition describes an add-one computation on a GPU:

from tvm_tirx.script import tirx as T

n = T.dynamic("n")


@T.function
def add_one(A: T.Tensor((n,), T.float32), B: T.Tensor((n,), T.float32)):
    T.device_entry(launch=T.cuda.LaunchConfig(grid=T.ceildiv(n, 256), block=256))
    i = T.cuda.block_idx("x") * 256 + T.cuda.thread_idx("x")
    if i < n:
        B[i] = A[i] + 1

add_one adds one to every element of a tensor A of length n and writes the result to B. Each GPU thread computes its index i and handles one element. At a high level, TIRx IR contains the following elements:

  • Types (ir.Type) describe the values that expressions produce, such as the scalar type T.float32 and the tensor type T.Tensor((n,), T.float32).

  • Expressions (ir.Expr) compute values, such as A[i] + 1 and the call T.cuda.thread_idx("x") to a registered operator (ir.Op).

  • Statements (ir.Stmt) describe what the program does and in what order, such as the if branch and the write B[i] = A[i] + 1.

  • Functions (ir.BaseFunc) wrap a body of statements with parameters, such as add_one.

  • Modules (ir.IRModule) group named functions into a complete program.

These IR nodes are designed to be generic, so that new IR variants can be built on top of them, and their namespaces show their roles. The ir namespace holds the common nodes shared by all variants. Within it, ir.prim (shown as prim) holds primitive expressions, which compute scalar or vector values of a primitive type (ir.PrimType), such as float32 or int32. These expressions concisely represent dynamic indices and element computations, such as A[i] + 1 in add_one. The tirx namespace builds on ir with the types and operations specific to tensor programs, such as tirx.Function and tirx.TensorType. More generally, TIRx is designed for extension: downstream projects can build on the IR in the same way, registering new operators, defining new types, and adding their own TVMScript namespaces from Python, C++, or Rust, while reusing TIRx as a foundation.

IR nodes can also carry source locations (ir.Location). For example, an expression’s loc field records where it came from in the source, so a diagnostic can point back to the original code.
