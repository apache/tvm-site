Types and Expressions#

In this chapter, we will introduce types and expressions. Expressions represent values and computations, and their types describe properties such as dtypes, tensor shapes, and function signatures. We will inspect the values in a small add-one function, then construct scalar and vector expressions through the IR API.

This CPU function reads each element of A, adds one, and writes the result to B. Both tensors have the same symbolic length n:

from tvm_tirx.script import tirx as T

n = T.dynamic("n")


@T.function
def add_one(A: T.Tensor((n,), T.float32), B: T.Tensor((n,), T.float32)):
    for i in range(n):
        B[i] = A[i] + 1

Types#

ir.Type is the base class for all IR types, including primitive types for scalar and vector values, tensor types, and function types:

We will examine primitive and tensor types first, then look at the pointer type used for a tensor’s data address.

PrimType#

ir.PrimType describes integer, floating-point, and boolean values, either as scalars or vectors. Its dtype records the element kind, bit width, and number of lanes.

In the program’s tensor annotations, T.float32 is an ir.PrimType("float32") object.

The tensor length n is an integer symbol:

from tvm_tirx.script import tirx as T

n = T.dynamic("n")

The default dtype is int32, so n has type ir.PrimType("int32"). The loop index i has the same primitive type.

We can express the addition A[i] + 1 directly through the IR API, with a scalar variable standing for the input element:

from tvm_tirx import ir
scalar_value = ir.Var("scalar_value", "float32")
scalar_plus_one = scalar_value + 1

scalar_value has type ir.PrimType("float32"), so it represents a single 32-bit floating-point value. The result scalar_plus_one has the same type, just like A[i] + 1 in the program.

PrimType also supports vector values. We can extend the same addition to four float32 values at once:

vector_value = ir.Var("vector_value", "float32x4")
vector_plus_one = vector_value + 1

The type of vector_value is ir.PrimType("float32x4"). The x4 suffix specifies four float32 lanes within one vector value. The addition adds one to each lane, and vector_plus_one has the same vector type.

TensorType#

tirx.TensorType is an IR type object that describes a whole tensor. It records the tensor’s dimensions and the type of each element.

The program declares its input and output as:

def add_one(A: T.Tensor((n,), T.float32), B: T.Tensor((n,), T.float32)):

T.Tensor((n,), T.float32) is the TVMScript notation for a tensor type; the parser represents it as a tirx.TensorType object. Its shape field contains one dimension, n, and its dtype field is ir.PrimType("float32"):

input_type = add_one.params[0].ty
print(ir.format_tree(input_type))

The output is:

TensorType
├── shape[0]: n = Var(ty=int32)
└── dtype: PrimType(dtype=float32)

The dimension n is symbolic: it is not fixed to a particular number when the function is compiled. Each call determines n from the length of A. Since B uses the same symbol in its type, its length must match A. The loop then uses n as its bound.

PtrType#

Some low-level operations take a memory address. The data property of a tensor parameter constructs an expression for its data pointer:

data_pointer = add_one.params[0].data
pointer_type = data_pointer.ty

pointer_type is an ir.PtrType. Its element_type is ir.PrimType("float32"), and its scope is "global", matching the tensor’s storage. This type describes the elements addressed by the pointer. The tensor’s TensorType also records their shape.

Expressions#

ir.Expr is the base class for expressions, which represent program values and computations. All expression classes inherit its ty field, which records the type of value they represent:

Field

Value type

Meaning

ty

ir.Type

The type of value represented by the expression.

We can inspect the types of scalar_value and scalar_plus_one through ty. Both are primitive types, so their dtype fields give the dtype names:

print(scalar_value.ty.dtype)
print(scalar_plus_one.ty.dtype)

The output is:

float32
float32

ir.Var("scalar_value", "float32") sets the variable’s type explicitly. The addition’s constructor determines its result type from its operands; this process is called type inference.

An expression under construction can also have an ir.MissingType in ty while its type is undetermined. Once its inputs are ready, the appropriate type rule can determine a concrete result type.

Each expression class adds fields for its value or operands, alongside the shared ty field:

Primitive Expressions#

A primitive expression is an expression whose ty is an ir.PrimType. This term groups expressions by their result type. Variables, tensor reads, arithmetic nodes, and calls can all belong to this group when they produce primitive scalar or vector values.

Scalar expressions. The CPU example uses the int32 expressions n and i for the loop bound and index. The tensor read A[i] and the addition A[i] + 1 both produce a single float32 value. A comparison such as i < n produces a boolean. These scalar result types are stored as PrimType objects in ty.

A itself represents the whole tensor and has a TensorType. The expression A[i] reads element i of this tensor. TVMScript represents the read as an ir.TensorLoad node. Its source field refers to A, and indices contains i, selecting the element to read:

loop = add_one.body.seq[0]            # The for loop.
addition = loop.body.seq[0].value     # The value written by its store.
element_read = addition.a
print(ir.format_tree(
    element_read,
    expand=[(ir.Expr, "ty"), "source"],
))

The output is:

TensorLoad(indices=[i])
├── ty: PrimType(dtype=float32)
└── source: A = Var(ty=TensorType(shape=[n], dtype=float32))

expand shows the read’s result type and the parameter referenced by source. The parameter’s tensor type remains folded on one line.

Vector expressions. A primitive expression can also produce a vector value. The earlier add-one result vector_plus_one has type ir.PrimType("float32x4"), representing four float32 lanes within one value.

A call whose result type is a PrimType also belongs to this category. For example, the GPU expression T.cuda.thread_idx("x") is an ir.Call with result type ir.PrimType("int32").

Primitive Operations#

Arithmetic and comparisons combine variables, constants, and tensor reads into larger expressions. The ir.prim namespace provides node classes and Python helpers for these operations, as well as boolean logic, casts, and other primitive computations:

Python expression

IR node constructed

scalar_value + 1

ir.prim.Add

ir.prim.sigmoid(scalar_value)

ir.Call to prim.sigmoid

Python operators such as +, *, and < construct arithmetic and comparison nodes. The Python helper ir.prim.sigmoid constructs a call to a registered operator; the returned IR node is an ir.Call.

In the CPU example, A[i] + 1 becomes an ir.prim.Add. A binary node stores its left operand in a and its right operand in b:

print(ir.format_tree(addition))

The output is:

Add
├── a: TensorLoad(source=A, indices=[i])
└── b: FloatImm(value=1.0)

The arithmetic constructor derives the result type from its operands. Since A[i] is float32, it converts the source literal 1 to the float32 constant shown as ir.FloatImm. The result is also float32.

These constructors also support vector operands. In vector_value + 1, the scalar constant is broadcast to all four lanes, producing the four-lane expression vector_plus_one.

A GPU version assigns one element to each thread. Its index calculation combines multiplication and addition, and its bounds check uses a comparison:

@T.function
def gpu_add_one(A: T.Tensor((n,), T.float32), B: T.Tensor((n,), T.float32)):
    T.device_entry(launch=T.cuda.LaunchConfig(grid=T.ceildiv(n, 256), block=256))
    i = T.cuda.block_idx("x") * 256 + T.cuda.thread_idx("x")
    if i < n:
        B[i] = A[i] + 1

The GPU launch uses 256 threads per block. The multiplication by 256 becomes an ir.prim.Mul, and the sum becomes an ir.prim.Add. The condition i < n is an ir.prim.LT whose a and b operands are the index and tensor length:

device_region = gpu_add_one.body.seq[0]
branch = device_region.body.seq[1]     # The if statement.
print(ir.format_tree(branch.condition))

The output is:

LT
├── a: i
└── b: n

The comparison checks whether the thread has a valid element to process.

Boolean operations combine comparisons into a single condition. For example, both checks must hold for a scalar to lie in the interval [0, 1):

in_unit_interval = ir.prim.And(scalar_value >= 0, scalar_value < 1)

The And node holds the two comparisons in a and b. Its result type is ir.PrimType("bool").

An operation can also change the dtype of a value. To produce a float16 version of the add-one result, we can use a cast:

half_plus_one = ir.prim.Cast("float16", scalar_plus_one)

The cast’s value field refers to scalar_plus_one. Its ty is ir.PrimType("float16"), which tells code generation to convert the float32 result to float16.

The ir.prim API reference lists other operations and their construction helpers.

Var#

ir.Var represents a named value with a type. Variables can be function parameters, loop indices, or intermediate values defined by bindings.

The tensor parameters A and B in our CPU function are represented by ir.Var objects. We can retrieve them from add_one.params and inspect their types through ty:

A, B = add_one.params
input_type = A.ty
output_type = B.ty

Each parameter is a Var with its own name and ty fields. We can expand its type to inspect the shape and element type:

print(ir.format_tree(A, expand=[(ir.Var, "ty")]))

The output is:

A = Var
└── ty: TensorType
    ├── shape[0]: n = Var
    │   └── ty: PrimType(dtype=int32)
    └── dtype: PrimType(dtype=float32)

The variable’s name appears before = Var. The ty edge leads to its tensor type, whose shape contains the integer symbol n. TVMScript creates these parameter variables when it parses the function. We can also create variables directly with ir.Var(name, ty). The scalar add-one example in PrimType uses this constructor:

from tvm_tirx import ir
scalar_value = ir.Var("scalar_value", "float32")
scalar_plus_one = scalar_value + 1

ir.Var("scalar_value", "float32") creates a variable whose name is "scalar_value" and whose ty is ir.PrimType("float32").

Tuples#

An expression can group several values into a tuple. For example, we can keep the original scalar and its add-one result together, then select the second value:

paired_values = ir.Tuple([scalar_value, scalar_plus_one])
second_value = ir.TupleGetItem(paired_values, 1)

paired_values.fields holds the two expressions. Its type is an ir.TupleType whose fields holds their types: two ir.PrimType("float32") objects. TupleGetItem records the tuple in tuple_value and the selected position in index. Index 1 selects scalar_plus_one, so second_value has type ir.PrimType("float32").

Call#

ir.Call represents a call to an operator or function. Its op field refers to the operator or function expression being called, and args holds the argument expressions. A registered operator is represented by ir.Op.

The GPU index calculation above uses T.cuda.block_idx("x") and T.cuda.thread_idx("x") to read the block and thread coordinates. These TVMScript helpers construct calls to registered CUDA operators. We can construct the thread-index call directly through the IR API:

from tvm_tirx import ir

op = ir.Op.get("tirx.cuda.thread_idx")
x_call = ir.Call(op, [ir.StringImm("x")])

op is the ir.Op object for tirx.cuda.thread_idx. The call’s op field refers to this object, and its args array contains the string expression "x". Its ty is ir.PrimType("int32"):

print(ir.format_tree(
    x_call,
    expand=[(ir.Call, "ty")],
    hide=["attrs", "ty_args"],
))

The output is:

Call(op=tirx.cuda.thread_idx)
├── ty: PrimType(dtype=int32)
└── args[0]: StringImm(value='x')

The "x" argument selects the x axis. When the compiled GPU function runs, this call reads the current thread’s x-axis coordinate within its block. The index arithmetic uses the coordinates returned by the thread-index and block-index calls to compute i.

A common extension of add-one is an activation applied to its result. We can pass the earlier addition expression scalar_plus_one to the built-in prim.sigmoid operator:

sigmoid_op = ir.Op.get("prim.sigmoid")
activated_plus_one = ir.Call(sigmoid_op, [scalar_plus_one])

The call’s argument is now the addition expression. We fold args to keep the arithmetic on one line and expand the call’s result type:

print(ir.format_tree(
    activated_plus_one,
    fold=["args"],
    expand=[(ir.Call, "ty")],
    hide=["attrs", "ty_args"],
))

The output is:

Call(op=prim.sigmoid, args=[Add(a=scalar_value, b=FloatImm(value=1.0))])
└── ty: PrimType(dtype=float32)

activated_plus_one.args[0] refers to scalar_plus_one, so sigmoid receives the addition’s result. The expression computes 1 / (1 + exp(-(scalar_value + 1))). The operator’s type rule gives the call the same type as its input, ir.PrimType("float32"). This call is therefore also a primitive expression. The Python helper ir.prim.sigmoid(scalar_plus_one) constructs the same call.

The Operators and Calls chapter also covers calls to IR functions and explains how registered operators provide result-type inference and argument validation.
