Types and Expressions#

Expressions represent program values and computations, while types describe properties such as dtypes, tensor shapes, and function signatures. This shared representation can be extended with custom types and operators. Programs using these constructs can be built, inspected, and transformed through the existing IR interfaces.

Types#

ir.Type is the base class for type objects, giving analyses and transformations a common interface across different kinds of values. It defines the following field:

Field

Value type

Meaning

loc

ir.Location

Source information for diagnostics. Defaults to UnknownLoc and does not affect structural comparison.

Concrete subclasses inherit loc and add fields describing different kinds of values. Common examples include:

Class

Describes

Additional fields

ir.PrimType

A scalar or vector dtype

dtype

ir.PtrType

A pointer’s element type and memory scope

element_type, scope

ir.TupleType

Ordered tuple field types

fields

ir.FuncType

Function argument and return types

arg_types, ret_type

tirx.TensorType

A tensor’s shape, element type, and storage properties

shape, dtype, scope, data_alignment, layout

Some of these fields refer to other type objects. For example, FuncType stores the types of a function’s arguments and result:

from tvm_tirx import ir, tirx
integer_type = ir.PrimType("int32")
signature = ir.FuncType([integer_type], integer_type)

signature describes a function that takes and returns int32 values. integer_type.dtype holds the int32 dtype descriptor; signature.arg_types[0] and signature.ret_type both refer to the integer_type object. Tuple fields and pointer element types similarly refer to other type objects.

tirx.TensorType combines an element type with shape and storage information:

tile_type = tirx.TensorType((8, 128), "float32")

tile_type describes an (8, 128) tensor. Its shape contains integer expressions for 8 and 128, and its dtype is ir.PrimType("float32"). Dimensions can also use variables and arithmetic.

Use == to compare type structure and same_as to compare object identity.

Expressions#

Expression nodes make the inputs to a computation explicit, so analyses can inspect its operands and transformations can replace parts of the computation. ir.Expr is the base class for these nodes. It defines these fields:

Field

Value type

Meaning

ty

ir.Type

Result type. ir.MissingType marks type information that has not yet been supplied or computed.

loc

ir.Location

Source information for diagnostics. Defaults to UnknownLoc and does not affect structural comparison.

Subclasses inherit ty and loc and add fields for their stored values or operands. The following examples show common expression classes and selected fields:

Classes (examples)

Represents

Additional fields

ir.Var

A variable

name

ir.IntImm, ir.FloatImm, ir.StringImm

Literal constants

value

ir.prim.Add, ir.prim.Sub, ir.prim.Mul

Binary arithmetic

a, b

ir.prim.EQ, ir.prim.LT

Comparisons

a, b

ir.Op

A registered operator

name, doc, args_info

ir.Call

A call to an operator or function

op, args, attrs, ty_args

ir.TensorLoad

A tensor element read

source, indices

Arithmetic and comparison nodes for primitive values are available under ir.prim. The binary nodes above store their left and right operand expressions in a and b.

Registered operators are themselves expressions of class ir.Op. Each has a name, such as prim.exp, and metadata describing its arguments. ir.Op.get retrieves the operator object by name; ir.Call uses it as the callee of an invocation:

exp_op = ir.Op.get("prim.exp")
value = ir.Var("value", "float32")
exp_call = ir.Call(exp_op, [value])

exp_call.op refers to exp_op, and exp_call.args contains the input value. The same operator object can be used by many calls, each with its own arguments. ir.prim.exp(value) is a helper that constructs this call form. Operators and Calls explains operator registration, attributes, type inference, and validation.

Operands and call arguments are themselves expressions, allowing these forms to be combined into larger computations.

To describe x + 1, create a variable with the integer type above and a constant of that type. Adding them constructs an Add expression:

x = ir.Var("x", integer_type)
added = x + ir.const(1, integer_type)

x is a Var and added is an Add. Both carry integer_type in their ty field. Reuse the same variable object when a symbol appears in several places: another ir.Var("x", integer_type) is a distinct symbol, even with the same name.

A tensor variable follows the same pattern, with a TensorType in its ty field. Its shape can reuse the integer expressions described above:

n = ir.Var("n", "int64")
tensor_type = tirx.TensorType((2 * n, 128), "float32")
tensor = ir.Var("A", tensor_type)
element = tensor[0, 0]

The first dimension stores the expression 2*n. The same n can appear in loop bounds and indices. The element load tensor[0, 0] is another expression, with type ir.PrimType("float32").

The symbol n has a known int64 type even though its value is not yet known. Constructing these types and expressions does not allocate tensor storage.

Register New Types#

Custom types let extensions describe their own kinds of values and use them in existing IR variables and function signatures. New types can be added from Python or Rust without modifying the C++ core. Define a subclass of ir.Type and register it under its own key. Its reflected fields let structural comparison and printing handle it in the same way as built-in types.

In Python, use tvm_ffi.dataclasses.py_class; in Rust, use tvm_ffi::rs_class and tvm_ffi::def_object_ref!.

For example, this type describes a pair of values by the types of its two components. In Python, the fields are annotated class attributes, and the constructor takes them in order:

from tvm_ffi.dataclasses import py_class
from tvm_tirx import ir
@py_class("my_ext.PairType")
class PairType(ir.Type):
    first: ir.Type
    second: ir.Type


pair = ir.Var("p", PairType(ir.PrimType("int32"), ir.PrimType("float32")))

In Rust, the object struct starts with the TypeObj it extends, and the generated new for PairTypeObj takes that parent object and then the fields:

use tvm_tirx::ir::{Location, Type, TypeObj};
use tvm_tirx::tvm_ffi::{self, def_object_ref, rs_class};

#[rs_class("my_ext.PairType", final)]
pub struct PairTypeObj {
    base: TypeObj,
    pub first: Type,
    pub second: Type,
}

def_object_ref!(pub PairType, Type, PairTypeObj);

impl PairType {
    pub fn new(first: impl Into<Type>, second: impl Into<Type>) -> Self {
        PairTypeObj::new(TypeObj::new(Location::unknown()), first, second).into()
    }
}

Once registered, the type can be assigned to variables and used inside other types, just like a built-in type.

See TensorType for the complete constructor and storage options, and tvm_tirx.ir for expression and type APIs. Download types_and_expressions.py for runnable examples from this chapter.
