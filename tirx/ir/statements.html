Statements#

In this chapter, we will introduce the statements that organize a function’s execution. Statements can be used to describe value bindings, tensor writes, and control flow. Statements take several forms, including sequences, branches, and loops. Sequences record execution order, while branches and loops determine which statements execute and how often. Compiler passes can use these structures to construct and transform programs, including bodies defined by custom operators.

Statement Sequences#

One of the most common statement types is ir.SeqStmt, which groups statements in execution order in its seq field. A sequence can serve as a function body or as the body of a branch or loop.

In our sigmoid example, each iteration binds the biased input before storing the sigmoid result. Reusing the tensor variables and indices from Var and the helper from Call, we can build this sequence:

biased = ir.Var("biased", "float32")
biased_value = X[i, j] + bias[j]
result = sigmoid(biased)

body = ir.SeqStmt(
    [
        ir.Bind(biased, biased_value),
        ir.TensorStore(Y, [i, j], result),
    ]
)

ir.Bind defines biased with the value of X[i, j] + bias[j]. The following ir.TensorStore evaluates the sigmoid expression result using that binding and writes the value to Y[i, j]. The sequence forms the body of the channel loop, which we examine next.

Control Flow and Scope#

Control-flow statements determine which parts of a program execute, how many times they execute, and when execution leaves a loop or function. TIRx provides ir.If for branching, ir.For and ir.While for loops, ir.Break and ir.Continue for loop control, and ir.Return for returning from a function.

The statements inside a branch or loop form its body. Branch bodies are stored in If.then_case and If.else_case, while loop bodies are stored in For.body and While.body. Each body is a SeqStmt and can contain further branches and loops.

An ir.For specifies a loop variable, begin and end bounds, a step, and an execution kind. The end bound is exclusive. ForKind.DEFAULT executes iterations in order; the ForKind API reference describes the other execution kinds.

The program processes one channel at a time. The surrounding loops cover samples and channels, keeping each tensor access within its bounds:

channel_loop = ir.For(j, zero, end, step, ir.ForKind.DEFAULT, body)
batch_loop = ir.For(i, zero, 2 * n, step, ir.ForKind.DEFAULT, channel_loop)

batch_loop advances i by one sample. channel_loop advances j by one channel, executing body at each step. Both loops use int64 variables, bounds, and steps. The channel loop stops before end, the channel count, so j ranges from 0 to channels - 1.

Scope determines where a definition can be used. ir.SeqStmt groups statements without introducing an additional scope. In the example, the sequence ensures that biased is bound before the TensorStore uses it, while the enclosing channel loop limits its visibility to that loop body. The loop variables i and j are likewise visible only within their loop bodies.

Some operators introduce their own statement bodies. ir.RegionStmt represents these using a registered operator, whose definition specifies the body’s parameters.

These scope rules also apply to programs built through the IR API. After construction, tirx.analysis.check_well_formed can check a function or module for invalid variable and tensor uses and misplaced loop-control statements.
