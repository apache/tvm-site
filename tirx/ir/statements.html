Statements#

In this chapter, we will introduce statements, which describe the actions a function performs and their execution order. A statement can bind an intermediate value to a variable, write a result to a tensor, or control execution through a branch or loop. These statements form the function’s body, which compiler passes can inspect and rewrite through the IR interfaces.

Statement Classes#

ir.Stmt is the base class for all statements, from bindings and tensor writes to sequences, branches, and loops:

Statement Sequences#

A function body often contains several statements that run one after another. ir.SeqStmt stores these statements in execution order in its seq field. The statements inside a loop or branch are also stored in a SeqStmt.

The CPU example writes one output element in each loop iteration:

for i in range(n):
    B[i] = A[i] + 1

The indented assignment B[i] = A[i] + 1 becomes an ir.TensorStore statement describing a write to a tensor element. The loop body is a SeqStmt containing this statement. We can also construct this body through the IR API, using the parameter variables from add_one:

from tvm_tirx import ir

A, B = add_one.params
i = ir.Var("i", "int32")
store = ir.TensorStore(B, [i], A[i] + 1)
body = ir.SeqStmt([store])

ir.TensorStore takes the destination tensor B, the index list [i], and the value expression A[i] + 1. These arguments populate its dest, indices, and value fields. ir.SeqStmt([store]) holds this store statement as its first entry:

body: ir.SeqStmt
└── seq[0]: ir.TensorStore                B[i] = A[i] + 1
    ├── dest: ir.Var                     B
    ├── indices[0]: ir.Var               i
    └── value: ir.prim.Add                A[i] + 1

When the compiled function runs, the store computes A[i] + 1 and writes the result to element i of B. We can retrieve this statement with body[0], which is shorthand for body.seq[0].

A small extension of the CPU loop names the addition’s result before writing it to the output:

for i in range(n):
    value = A[i] + 1
    B[i] = value

The assignment to value becomes an ir.Bind statement: its var field holds the variable, and its value field holds the addition expression. The following TensorStore uses that variable as the value to write. We can construct these two statements and put them in a sequence:

value = ir.Var("value", "float32")
binding = ir.Bind(value, A[i] + 1)
store_from_value = ir.TensorStore(B, [i], value)
sequence = ir.SeqStmt([binding, store_from_value])

sequence: ir.SeqStmt
├── seq[0]: ir.Bind                      value = A[i] + 1
│   ├── var: ir.Var                      value
│   └── value: ir.prim.Add               A[i] + 1
└── seq[1]: ir.TensorStore               B[i] = value
    └── value → same ir.Var              value

When the function runs, the binding computes the addition and defines value, then the store writes this value to B[i]. The next section places the original single-store body inside the CPU loop.

Control Flow#

Control-flow statements determine which parts of a program execute and how often. A loop repeats a body of statements, while a branch selects which body runs.

The CPU example visits every element with a loop:

for i in range(n):
    B[i] = A[i] + 1

The loop becomes an ir.For. Its var field identifies the loop variable i, and its body field holds the SeqStmt containing the tensor store. We can construct this loop using i and body from the previous section:

loop = ir.For(i, 0, n, 1, ir.ForKind.DEFAULT, body)

The arguments 0, n, and 1 set the begin, end, and step fields. ForKind.DEFAULT selects execution in iteration order. On each iteration, the loop executes the statements in body:

loop: ir.For
├── var: ir.Var                           i
├── begin: ir.IntImm                      0
├── end: ir.Var                           n
├── step: ir.IntImm                       1
├── kind: ir.ForKind.DEFAULT
└── body: ir.SeqStmt
    └── seq[0]: ir.TensorStore            B[i] = A[i] + 1

The end bound is exclusive, so i runs from 0 through n - 1. Each iteration executes the store in body with that value of i. The loop defines i for use inside For.body, which is its scope. The For establishes this scope, and its SeqStmt body records the order of the statements within it. The ForKind API reference describes the other execution kinds.

The GPU example distributes this work across threads. T.device_entry introduces the GPU computation. Each thread computes an index i and checks whether it has an element to process:

T.device_entry(launch=T.cuda.LaunchConfig(grid=((n + 255) // 256,), block=(256,)))
i = T.cuda.block_idx("x") * 256 + T.cuda.thread_idx("x")
if i < n:
    B[i] = A[i] + 1

The if i < n becomes an ir.If. Its condition field holds the comparison, an ir.prim.LT expression. Its then_case field holds a SeqStmt containing the tensor store:

ir.If
├── condition: ir.prim.LT                 i < n
├── then_case: ir.SeqStmt
│   └── seq[0]: ir.TensorStore            B[i] = A[i] + 1
└── else_case: None

The condition produces a boolean. When it is true, the thread executes the store in then_case. An else branch has its own SeqStmt in else_case. This example has no else branch, so else_case is None and threads whose indices are outside the tensor perform no tensor access. These branch bodies can also contain further loops and branches.

The standalone T.device_entry(...) groups the remaining statements in this function into a device region. An ir.RegionStmt represents this region in the IR. Its op identifies tirx.device_entry, and its body is a SeqStmt containing the index definition followed by the branch:

ir.RegionStmt
├── op → ir.Op                          tirx.device_entry
└── body: ir.SeqStmt
    ├── seq[0]: ir.Bind                 i = ...
    └── seq[1]: ir.If                   if i < n
        └── then_case: ir.SeqStmt
            └── seq[0]: ir.TensorStore  B[i] = A[i] + 1

The Bind defines i before the If uses it. The variable is available to the condition and tensor store within the region. The Printing and Parsing chapter explains the grouping rule for this standalone syntax and the equivalent with form.
