Operators and Calls#

In this chapter, we will introduce operators and calls, from an operator’s shared definition to the arguments and result type of an individual call. We will examine argument requirements, type inference, validation, and effects. Built-in and custom operators share the same IR representation, so compiler passes can inspect and transform both through the existing interfaces.

Operators#

ir.Op is an expression that identifies a registered computation. We can retrieve it with ir.Op.get(name) and inspect args_info for the expected inputs.

Operator attributes describe properties shared by all calls to that operator. The TCallEffectKind attribute records whether a call only computes a value or can read or change program state.

The program uses the same exponential operator for each input element. Its shared argument and effect information can be inspected through the operator:

op = ir.Op.get("prim.exp")
argument_names = [argument.name for argument in op.args_info]
effect = op.get_attr("TCallEffectKind")

argument_names is ["x"], and effect is ir.CallEffectKind.Pure. This means the exponential call computes its result from its input without reading or changing external state. The tensor loads supplying that input are separate expressions. The Op API reference describes its argument information and attributes.

Calls#

ir.Call represents an invocation of an operator or function. The expression being called is its callee. The call records that callee, its arguments, and any attributes for the invocation:

Field

Meaning

op

The callee: a registered operator or another function-valued expression.

args

Value arguments in calling order.

ty_args

Explicit type arguments, empty by default.

attrs

Attributes for this invocation, or None. A dictionary becomes ir.DictAttrs.

In the bias + sigmoid example, the activation can be an expanded expression, 1 / (1 + exp(-x)), or a single call to prim.sigmoid. A named activation operator lets a later compiler pass choose its implementation:

x = ir.Var("x", "float32")
call = ir.prim.sigmoid(x)

ir.prim.sigmoid is a helper that constructs an ir.Call to the registered prim.sigmoid operator. In this example, it is equivalent to ir.Call("prim.sigmoid", [x]), which resolves the operator name through ir.Op.get. The call’s result has the same type as x: float32 in this example.

In the example above, constructing call records the sigmoid computation in the IR; the computation runs when the compiled program executes. The same ir.Call representation can invoke a function as well as a registered operator. For example, its op field can hold a global reference to a function in a module, as we’ll see in Functions and Modules.

Type Inference and Validation#

ir.Call can infer its result type from the operator’s registered rule or the callee’s function signature. The constructor infers the type when ty is omitted and stores the supplied type when ty is explicit. MissingType marks a result whose type has not yet been determined. For example:

x = ir.Var("x", "float32")
ir.Call("prim.exp", [x])                        # Infers float32.
ir.Call("prim.exp", [x], ty="float32")          # Uses the supplied float32.
ir.Call("prim.exp", [x], ty=ir.Type.missing())  # Keeps MissingType; no inference.

Validation checks whether the arguments meet the operator’s requirements. It is separate from construction, so tools can assemble a call before checking its arguments with call.validate(). Type inference can also reject inputs while computing the result type.

To see how validation catches missing arguments, we can construct a prim.exp call with no input and an explicit result type:

invalid = ir.Call("prim.exp", [], ty="float32")
invalid.validate()

The explicit result type bypasses type inference. invalid.validate() then raises TypeError because prim.exp requires one input argument.

When a pass rebuilds a call, its result type must match the arguments. Here, exp_call represents T.exp(-biased), whose input is a float32 value. The following code reconstructs the call with a missing type, then uses ir.reinfer_type to infer its result type:

provisional = ir.Call(op, exp_call.args, ty=ir.Type.missing())
inferred = ir.reinfer_type(provisional)
rebuilt_call = ir.Call(op, provisional.args, ty=inferred)

inferred is ir.PrimType("float32"), matching the input’s type. The inference function returns this type without changing provisional; rebuilt_call stores it in its ty field. The rebuilt call can then be checked with rebuilt_call.validate() before a pass uses it in place of the original.
