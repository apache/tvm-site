C++ API#

This page contains the API reference for the C++ API. The full API index below can be a bit dense, so we recommend the following tips first:

  • The Key Classes lists the key classes that are most commonly used.

  • See Header Organization for how the modules are organized.

  • TVM-FFI Structural Utilities lists the TVM-FFI utilities for walking and rewriting IR.

  • You can go to the Full API Index at the bottom of this page to access the full list of APIs.

    • We usually group the APIs by files. You can look at the file hierarchy in the full API index and navigate to the specific file to find the APIs in that file.

Header Organization#

The C++ headers are organized into the following folders, in dependency order: each folder builds on those above it.

Folder

Description

tvm/ffi/

From TVM-FFI: objects, containers, functions, and the structural utilities (see TVM-FFI Structural Utilities).

tvm/support/

Minimal runtime foundation for executing compiled code.

tvm/ir/

Core IR that language variants build upon, extend, and customize.

tvm/script/

tvm/tirx/

tvm/codegen/

Generic host code generation and intrinsic lowering rules.

tvm/backend/

Backend-specific attributes, intrinsics, passes, and code generation.

Key Classes#

This section lists the key classes of the core IR and tensor programs.

The IR follows a common convention: each IR node is a TVM FFI Object whose class name carries the Obj suffix, such as tvm::prim::AddObj, paired with a named managed reference class, such as tvm::prim::Add. C++ extensions written against the former FooNode spelling must use FooObj and rebuild. Managed reference names, runtime type keys, and serialized identities remain unchanged. A reference class can define its own constructors, operators, and member functions, and inherit from other reference classes to share and specialize its interface. It can also impose additional constraints on the node it holds, as described below. The tables list the reference classes; to find the node class behind a reference, check its ContainerType member. IR reference classes are non-nullable; use ffi::Optional<T> when a value may be absent. See also Object and Class.

Besides the named reference for each node, some reference types add constraints on the node they hold. For example, TypedExpr<T> holds any tvm::ExprObj whose ty field is a T, and tvm::PrimExpr, defined as TypedExpr<PrimType>, holds any ExprObj whose ty is a tvm::PrimType. These constraints are defined by the TVM FFI TypeTraits specialization of the reference type.

TVM-FFI Structural Utilities#

TIRx builds on TVM-FFI and supports it as a first-class foundation. Every TIRx IR node is a TVM-FFI object that is shared across languages, so TIRx uses the native TVM-FFI utilities for walking and rewriting IR directly. We list these utilities here for completeness. See the TVM-FFI documentation for more details.

See also

The headers tvm/tirx/structural_visit_with_constraint_context.h and tvm/tirx/structural_mutate_with_constraint_context.h provide variants of these utilities that also track constraint information, such as loop ranges and branch conditions, at each node: tvm::tirx::StructuralWalkWithConstraintContext(), tvm::tirx::StructuralVisitWithConstraintContext(), tvm::tirx::StructuralMapWithConstraintContext(), and tvm::tirx::StructuralMutateWithConstraintContext().
