Registering IR types from Rust: register_type, which a tvm_ffi::static_init_block! calls for an rs_class type, as C++ registers a type with refl::ObjectDef in a TVM_FFI_STATIC_INIT_BLOCK.

rs_class registers the fields of a type and, as C++ refl::ObjectDef does, a creator of an object whose fields are undefined, which tvm-ffi fills through the reflection of the fields to construct the type from Python (the __ffi_init__ it generates) and to read it from a JSON graph (__ffi_new__). register_type registers the type when its program or library loads and exposes its constructor to Python.

Functions§

  • register_type
    Register the IR type of the reference R, an rs_class type, as C++ registers one with refl::ObjectDef: the type, with the __ffi_new__ and __ffi_init__ rs_class registers, then, when the receiver is installed, a request for its constructor in registered destinations (ir.expose_type); an absent receiver is a no-op, and an installed receiver’s error is returned. With an explicitly declared my_ext type API destination, Python then constructs the type from its fields, my_ext.Pair(T.int32, second=T.float32), as it constructs a C++ type, and a JSON graph holds it. Import tvm_tirx before loading the library so exposure requests reach Python. Import the extension module in Python scope, or supply it to text parsing through imports, extra_vars or explicit parser namespace registration; type exposure does not add parser defaults.
