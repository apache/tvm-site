Register the IR type of the reference R, an rs_class type, as C++ registers one with refl::ObjectDef: __ffi_new__, from the Placeholder of the object, then the __ffi_init__ tvm-ffi generates from the reflected fields, then, when the receiver is installed, a request for its constructor in registered destinations (ir.expose_type); an absent receiver is a no-op, and an installed receiver’s error is returned. With an explicitly declared my_ext type API destination, Python then constructs the type from its fields, my_ext.Pair(T.int32, second=T.float32), as it constructs a C++ type, and a JSON graph holds it. Import tvm_tirx before loading the library so exposure requests reach Python. Import the extension module in Python scope, or supply it to text parsing through imports, extra_vars or explicit parser namespace registration; type exposure does not add parser defaults.

Call it in a [tvm_ffi::static_init_block!], with the OpDef chains of the operators, so that the type is registered when its program or library loads, as a C++ one is; the type’s struct, reference and impls are written outside the block, as any other:

use tvm_tirx::ir::{register_type, Location, Placeholder, Type, TypeObj};
use tvm_tirx::tvm_ffi::{self, def_object_ref, rs_class, ObjectRefCore};

/// The type of a pair of values, printed as `my_ext.Pair(first, second)`.
#[rs_class("my_ext.PairType", final)]
pub struct PairTypeObj {
    base: TypeObj,
    pub first: Type,
    #[reflect(kw_only)]
    pub second: Type,
}
def_object_ref!(pub PairType, Type, PairTypeObj);

impl Placeholder for PairTypeObj {
    fn placeholder() -> Self {
        Self::new(TypeObj::placeholder(), Type::placeholder(), Type::placeholder())
    }
}

impl PairType {
    pub fn new(first: impl Into<Type>, second: impl Into<Type>) -> Self {
        PairTypeObj::new(TypeObj::new(Location::unknown()), first, second).into()
    }
}

tvm_ffi::static_init_block! {
    register_type::<PairType>()?;
}
