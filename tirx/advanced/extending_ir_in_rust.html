Getting Started with Rust Extensions#

Note

All the code in this tutorial is in the repository, as the Python package examples/extension.

TIRx is designed around the idea that “everything is a plugin”: compiler features can be provided by separately built libraries, using the same IR and registration interfaces as built-in features. This tutorial shows how to write such a library in Rust.

Case Study: Complex Numbers#

To show “everything is a plugin” in practice, we use complex numbers as an example. All complex-number support comes from an extension that loads into TIRx without modifying its core library.

Our goal is that, once the extension is loaded, complex types and operators are written in TVMScript just like built-in ones, and functions that use them compile with TIRx. For example, the following function multiplies two complex tensors element by element. A and B hold the real and imaginary parts of the first tensor, C and D those of the second. We will compile and run it at the end of the tutorial.

N = 16


@T.function
def complex_product(
    A: T.Tensor((N,), "float32"),
    B: T.Tensor((N,), "float32"),
    C: T.Tensor((N,), "float32"),
    D: T.Tensor((N,), "float32"),
    R: T.Tensor((N,), "float32"),
    Im: T.Tensor((N,), "float32"),
):
    for i in range(N):
        z = my_ext.complex(A[i], B[i])
        w = my_ext.complex(C[i], D[i])
        product = my_ext.cmul(z, w)
        R[i] = my_ext.real(product)
        Im[i] = my_ext.imag(product)

my_ext is the extension’s Python package, which holds the builders of its type and operators; Using and Compiling the Extension shows how it provides them. z, w, and product are complex values that exist only in the IR. The function’s inputs and outputs are ordinary float32 tensors, so no runtime storage format for complex numbers is needed.

Code generation has no complex type, so by the time the function reaches the backend, every complex value must be a pair of float32 values. Expanding complex multiplication as

(a + bi)(c + di) = (ac - bd) + (ad + bc)i

gives the loop we want the compiler to produce:

for i in range(N):
    z_re: T.let[T.float32] = A[i]
    z_im: T.let[T.float32] = B[i]
    w_re: T.let[T.float32] = C[i]
    w_im: T.let[T.float32] = D[i]
    product_re: T.let[T.float32] = z_re * w_re - z_im * w_im
    product_im: T.let[T.float32] = z_re * w_im + z_im * w_re
    R[i] = product_re
    Im[i] = product_im

z, w, and product have each become a pair of variables for the real and imaginary parts, and only scalar arithmetic remains.

To support complex numbers as a custom type, we need:

  1. A type. For TIRx to recognize complex values, a complex type, the type of z, w, and product.

  2. Operators. For TIRx to compute on complex values, the operators complex, cmul, real, and imag, which build complex values, multiply them, and read their parts.

  3. A lowering pass. For the target to compile the function, LowerComplex, which lowers the complex type and operators to the scalar arithmetic above.

Note

An extension can also add passes that optimize computations on its types, for example to simplify a product with a known real factor. They are written the same way as the lowering pass, so the example shows only the latter.

The rest of this page sets up the extension’s Python package. Defining Types, Operators, and Passes then defines the type, operators, and pass, and Using and Compiling the Extension compiles and runs the function.

Setting Up the Project#

An extension can be shipped as a Python package that contains its Rust library (or written in pure Python, like the version shown beside Rust in Defining Types, Operators, and Passes), so it can be installed and imported like any other package. The example package, my-ext, has this layout:

examples/extension/
├── Cargo.toml        # the Rust library, which depends on tvm-tirx
├── src/lib.rs        # the type, operators, and pass
├── CMakeLists.txt    # builds the library with cargo and installs it into my_ext
├── pyproject.toml    # the Python package, built with scikit-build-core
├── python/my_ext/    # loads the library and registers a compilation pipeline
└── run_example.py    # compiles and runs a function that uses the extension

The Rust library is an ordinary crate that builds a shared library. It depends on the tvm-tirx crate, which re-exports TVM FFI as tvm_tirx::tvm_ffi, and also lists tvm-ffi itself, because the code that #[dispatch] generates refers to the crate by that name:

[lib]
# The shared library that the Python package loads.
crate-type = ["cdylib"]

[dependencies]
# This example builds against this checkout. A standalone extension depends on
# the published releases instead, e.g. tvm-tirx = "<version>".
tvm-tirx = { path = "../../rust" }
# Procedural macros resolve the FFI crate directly; use the same pinned sources.
tvm-ffi = { path = "../../3rdparty/tvm-ffi/rust/tvm-ffi" }

First build and install TIRx from this checkout. With Rust 1.95 or newer, install the extension from the repository root in the same Python environment:

uv pip install scikit-build-core
uv pip install --no-build-isolation --no-deps ./examples/extension

The example uses this checkout’s Rust crate and pinned TVM FFI sources. The package depends on apache-tvm-tirx at run time; disabling build isolation keeps its native build aligned with these sources instead of installing a released package in a temporary build environment.
